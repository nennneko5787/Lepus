## なぜこれが候補か

直したBugと機構が同じです。v13 は「**装着者**の回転 × パック」をepaar、v14 は
「**ジオメトリの宣言された回転** × 同じ骨のア���メーション」を問う。まだ測っていない対。

コーパスで**宣言された回転と ��ニメーション position を両方持つ骨**がちょうど数少ない:

| 骨 | 宣言 rotation | position を持つアニメ |
|---|---|---|
| **`bag2`（盾）** | **`[0, 180, 60]`** | `.hand` `position [0,1,1]` |
| `leftArm2` | `[0, 0, -12.5]` | idle `position [0,1,-1]` |
| `halo2` | `[-45, 0, 0]` | idle `position`（t=0 では 0） |

**`bag2` だけが、その二つの組み合わせで deployment の中心から外れている。**

**本実装は「運ぶ」**（`BoneMatrices.local` が `T(P)·R_bind·extra·T(-P)` の順なので
宣言回転が `extra` の位置を胞ます）。逆にした場合のずれは**測った**:
`bag2` の上端が y 34.43 → 31.09（**3.3 units ≒ 0.21 ブロック分、下に**）動く。
ただし `leftArm2` も歪むので、**推测で入れるには速すぎる**。

**v9/v10 は同じ bones の own 回転（アニメ由来）が own position を運ばないと確定した。**
宣言回転については「v9/v10 と同じ理屈」という議論はできるが、それは**測っていない**。

## 読んでほしいもの（2 問、**一番下の棒と比較するだけ**）

画面には棒が **3 本**、縦に並びます。一番下の棒を基準に。

| # | 棒 | 質問 | 本実装の予測 |
|---|---|---|---|
| **1** | **一番上** | **一番下と並列か、直交か** | **直交**（＝宣言回転が運ぶ）★本丸 |
| **2** | **真ん中** | **一番下と並列か、直交か** | 直交（アニメ回転が運ぶ。v12 の結果） |

**質問 2 は v12 の再確認**なので、预期通り「直交」でなければ v12 の読みがアニメ由来に限られる rationally ないことを意味します。**質問 1 が本丸。**

- **質問 1 が「直交」** → 本実装と一致。盾の高さの原因は**別の場所**なので、v13 と同じ問屋をこれ以上重ねず、`bag2` 固有の何かを測る
- **質問 1 が「並列」** → 宣言回転は own position を**運ばない** = **これが盾の原因**。v13 と同型のバグで、実装を直す
