# v16 — 親の**回転**が子の position を運ぶか（**深度不要**で読める設計）

v12 / v14 が同じ問いに違う答えを出しました。**両方の rig が駄目でした**:

- v12 は「上から 2 本目」という指示を使った。**この合成だと 2 本が全然違う位置に来て、その指示が成立しない**
- v14 / v15 は三人称カメラで読んだ。**Z 方向の棒と X 方向の棒は、短縮率の差でしか区別できず、それはカメラが決めた見角度**

## v16 の違い — **上下か、左右か** しか使わない

回転を **roll（Z 軸）90°** にして、子の position を **真上 `[0,24,0]`** にする。

| | 運ぶ（= 本実装） | 運ばない |
|---|---|---|
| `m_roll`（スラブ） | **左右**に出る（X = ±24） | **真上**（Y = +24） |

**上下と左右は、どの視点からでも深度の判断なしで読めます。** 三人称カメラの弱点を entirely 回避。

## 中身（マーカーは 2 つだけ）

```
root
 ├ arm_roll  ← アニメ rotation [0, 0, 90]（roll）
 │   └ m_roll  pivot [0,0,0]     スラブ 8×2×2   position [0,24,0]
 └ arm_none  ← 回転なし
     └ m_none  pivot [0,-24,0]   キューブ 3×3×3  position [0,24,0]
```

`m_none` は回転する親を持たないので、**必ず原点 `[0,0,0]` に着地します**。
`m_roll` が `m_none` の**横**か `m_none` の**上**か — それだけを答えます。

## 手順（統合版）

1. `lepus_probe16.mcaddon` を読み込み、**BP と RP 両方**を有効化
2. `/give @s lepus:probe16`
3. メインハンドに持って **三人称（F5）。視点は動きません**

## 読んでほしいもの（**1 問だけ**）

> **スラブ（平たい板）は、キューブの「横」ですか、それとも「上」ですか？**

**本実装の予測は「横」**（= 運ぶ）。

- **「横」** → v12 が正しかった（本実装と一致）。盾の原因は**別の場所**
- **「上」** → アニメ回転は position を運ばない。盾の原因はこれ

## 教訓

| 失敗 | 対策 |
|---|---|
| v12: 順序で指示した | 順序を使わない |
| v14/v15: 三人称カメラで深度を読ませた | **上下と左右だけ**を使う |
| v15: 形を変えても読めなかった | 位置の二択にした |
