# v15 — 矛盾した読み（v12 と v14）を、**形で**決着させる

**v12 と v14 が同じ問いに違う答えを出した。** v12 の侧的設計が間違うので、
**v14 の読み**（アニメ回転は運ばない）を採用する前に、bar の同一視FAFAれる way で 1 本だけ追加する。

## 矛盾

| 読み | 問い | 本実装 | 実機 |
|---|---|---|---|
| v12 ② | 親の**アニメ**回転が子の position を運ぶか | 運ぶ | **運ぶ** |
| **v14 ②** | **同じ質問** | 運ぶ | **運ばない** |

**v12 の質問が成立していなかった。** v12 は「上から 2 本目と 1 本目を比べろ」と指定したが、
この合成だと 2 本は全然違う位置にきて so「上から 2 本目」という指定そのものが壊れる。
**読者が間違えたのではなく、質問 못한 질문だった。**

v14 は「3 本全部を一番下と比べる」という形にしたので曖昧性がなく、**そちらが信頼できる。**

## v14 の読みが正しいと仮定すると一式がconsistentになる

| | 回転の出所 | position を運ぶか |
|---|---|---|
| v9/v10 | 骨自身の**アニメ**回転 | **運ばない** |
| v14 ② | **親のアニメ**回転 | **運ばない** |
| v14 ① | **宣言された**回転 | **運ぶ** |
| v13 | **装着者**の回転 | **運ぶ** |

**宣言と外部は運ぶ、アニメーションは運ばない。** そしてこれは `bag2` に直接効く
（`bag2` は `leftArm2` の子で、`leftArm2` の回転は**アニメ**由来）。

## v15 で消除する曖昧性

**3 つのマーカーを 3 つの違う形にする。** 向きが何であれ形は_wrapping_ で分かる。

| | 形 | 何のテストか |
|---|---|---|
| `m_bind` | **横棒**（12×1×1，细い） | **宣言された**回転が運ぶか（v14 ① の再現） |
| `m_anim` | **ブロック**（4×3×3，短くて太い） | **アニメ**回転が運ぶか（v12/v14 ② の決着）★本丸 |
| `m_flat` | **キューブ**（3×3×3） | 対照。X 方向にあるはず |

**質問は形ごとに 1 個ずつ。「キューブから横（X）にあるか、奥（Z）にあるか」だけ。**

## 読んでほしいもの（2 問、**形は付きで**）

画面には 3 つの赤いやつ。**キューブ（对照）が横向きにあるのが正解の基準。**

| # | 形 | 質問 |
|---|---|---|
| **1** | **ブロック**（4×3×3） | **キューブの横（X）に並んでいるか、キューブの真後ろ/手前（Z）にいるか** ★本丸 |
| 2 | 横棒（12×1×1） | キューブの横か、奥か |

**本実装の予測は両方とも「奥（Z）」**（= 両方とも運ばれる）。だから:

- **質問 1 が「横」** → v14 ② が正しかった。**アニメ回転は position を運ばない**。`bag2` の高さはこれ
- **質問 1 が「奥」** → v12 が正しかった（本実装と一致）。盾の原因は**別の場所**

質問 2 は v14 ① の再現で、**「奥」になるはず**。それが「横」になったら前問が両方崩れるので、
**そこだけ先に教えてくれれば十分**。
