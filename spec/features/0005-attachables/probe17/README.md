# v17 — **ゼロ軸の cube で Bedrock はどの面を描くか**（色鍵で決着）

ハロー（`halo2`: `size [12,0,10]` / `uv [-10,54]`）が**二人のキャラで両方出ない**のに、
**Bedrock Edition では両方出る**。つまりこれは私たちのバグで、
**`BoxUv` がゼロ軸の cube に落とす面を間違えている**疑いがある。

`BoxUv` の javadoc がちょうどこう書いている — **この配置は「asserted, not verified」**。

## テクスチャで聞く（推測しない）

**64×64 の自作テクスチャ**に、候補のスロットごとに**塗り分けた色**を置いてある。
**出的る色が、そのまま「Bedrock が描いた面」を答える。**

| 塗り | スロット | 谁的 cube |
|---|---|---|
| **シアン** | uv (0,0)-(2,3) | ゼロ**深度** の NORTH |
| **マゼンタ** | uv (2,0)-(4,3) | ゼロ**深度** の SOUTH |
| **赤** | uv (0,54)-(12,64) | ゼロ**高さ** の UP |
| **緑** | uv (12,54)-(24,64) | ゼロ**高さ** の DOWN |

**この配置は本リポジトリの `BoxUv.expand` が今Assignしている位置そのもの。**
別の面を選ぶ ≠ 別のテクスチャ領域、という構造。

## ジオメトリはコーパスの**そのもの**の宣言

```json
{ "origin": [-1, 30, 0], "size": [2, 3, 0], "uv": [0, 0] }        ← eye2 と同型（ゼロ深度）
{ "origin": [6, 10, -5], "size": [12, 0, 10], "uv": [-10, 54] }  ← halo2 と同型（ゼロ高さ）
```

**.Models も `uv` も書き換えていない。** 変数declared はゼロ軸の向きだけ。

2. `/give @s lepus:probe17`

## 読んでほしいもの（**色だけ**。位置も大きさも関係없다）

| # | 見える形 | 質問 |
|---|---|---|
| **1** | **小さい方**（2×3 の平たい四角） | **シアン**か **マゼンタ**か |
| **2** | **大きい方**（12×10 の平たい四角） | **赤**か **緑**か |

## 本実装の予測

本実装は `AttachableGeometry.flatFace` で、深度ゼロなら `SOUTH`・高さゼロなら `UP` を**落とす**。
つまり**描くのは NORTH と DOWN**:

| | 本実装の予測 | もし逆なら |
|---|---|---|
| 小さい方 | **シアン**（NORTH） | マゼンタ（SOUTH） |
| 大きい方 | **緑**（DOWN） | **赤**（UP） |

**大きい方が「赤」なら、それが光輪のバグ** — 両方 حالي DROP している面を描いている。
