# v12 — 親の**アニメーション**回転が、子のアニメーション位置を運ぶか

**v11 は「親の回転」と「親→子の階層」を 1 本のプローブに重ねて失敗した。** Goals ではなく**実装上の欠陥**の記録。

## v11 で測れたこと（Bedrock 実機、報告者）

| | 結果 |
|---|---|
| 1（上の棒と真ん中の棒の向き） | **同じ方向** — 本実装は直交（Z を向く）と予測 |
| 2（下の棒） | 真ん中より下・やや長く大きい — 本実装は 1.5 倍と予測 |

## v11 が答えられなかった理由 — **親の回転を_bind_ で書いた**

ホシノの `root2` の `−85°` は**アニメーション**由来である:

```json
"root2": { "rotation": [0,-85,0], "position": [-32,-2,-9], "scale": 1.2 }   ← .hand
"root2": { "rotation": [22.5, 0, 22.5], "position": [1, 0, 5] }             ← idle
```

v11 はこれを**ジオメトリの宣言回転**として書いていた:

```json
{ "name": "arm_yaw", "rotation": [0, 90, 0] }     ← bind。別経路
```

**2 つの問いが混ざった:**

- (a) 宣言された親の回転は、子の**ジオメトリ**を回すか ← v11 はこれしか測っていない
- (b) 親の回転は、子の**アニメーション position** を運ぶか ← ホシノが実際に ASK ている問い

(a) が「否」なら、棒が横を向くだけで (b) の情報は出ない。v11 の観測は (a) の否を
istruzione )!
可能性が高く、**ホシノの件には何も言えない**。

## v12 の違い

| | v11（失敗） | v12 |
|---|---|---|
| 親の回転 | ジオメトリの `rotation` | **アニメーション**の `rotation` ← ホシノと同じ経路 |
| 階層のテスト | 無し | **`m_yaw2`**: 親だけ回転、子は**アニメーション無し** |
| position のテスト | 有 | 有（`m_yaw`） |
| scale のテスト | 有 | 有（`m_scale`） |

`m_yaw2` が本次の肝で、**自分のアニメーションが 1 つも無い**。だから観測された向きは
(-animation_a) の直接の答えになる。

## 中身（上から 4 本の棒）

```
root
 ├ arm_yaw                     ← アニメ rotation [0,90,0]
 │   ├ m_yaw2  pivot [8,16,0]   自分のアニメ無し  …(a) 階層のテスト
 │   └ m_yaw   pivot [0, 8,0]   position [8,0,0]  …(b) position を運ぶか
 ├ arm_flat
 │   └ m_flat  pivot [0, 0,0]   position [8,0,0]  … 対照
 └ arm_scale                   ← アニメ scale 1.5
     └ m_scale pivot [0,-12,0]  position [8,0,0]  …(c) scale を運ぶか
```

## 読んでほしいもの（3 問、**主観 ANS 不要・的都是「並列か直交か」**）

画面には棒が **4 本**、上から順に:

| # | 棒 | 質問 | 判定 |
|---|---|---|---|
| **1** | 一番上 | **Z（前后）を向いているか、X（左右）を向いているか** | (a) |
| **2** | 上から 2 本目 | **一番上の棒と並列か、直交か** | (b) ★本丸 |
| **3** | 一番下 | **他の棒より 1.5 倍長いか、同じか** | (c) |

**本実装の予測**（すべて「運ぶ」）:
1 = Z を向く / 2 = **一番上と並列** / 3 = 1.5 倍長い

**質問 2 が本丸。** ここが「並列」なら §4.1 の親‑子区間は正しく、**ホシノの原因は別にあり**、
v9/v10 が確定させた骨自身の順序か `query.target_*_rotation` の一人称の値へ戻って切り分け直す。
「直交」なら**これが原因**で、実装を直す。
